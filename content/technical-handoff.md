# การเตรียมเปิดใช้งานเว็บไซต์

สถานะ: เตรียมระบบในเครื่องพัฒนา ยังไม่มีการ deploy และบทความทั้งสองยังเป็นร่าง

แผน hosting ปัจจุบันใช้งบ 0 บาท: ส่งออก HTML/CSS ไป GitHub Pages และเก็บ CMS ในเครื่อง รายละเอียดอยู่ใน `github-pages-guide.md` ส่วน hosting Node.js, ฐานข้อมูล และอีเมลด้านล่างเป็นทางเลือกภายหลังหากต้องการเปิด CMS ออนไลน์

## สิ่งที่เตรียมแล้ว

- Next.js, Payload CMS และ PostgreSQL พร้อมหน้าผู้อ่านและหน้าทีมงาน
- ร่างบทความทั้งสองและชุดเอกสารส่งตรวจ
- การอนุมัติผูกกับเวอร์ชันเนื้อหา การแก้เนื้อหาต้องตรวจใหม่
- Initial migration สำหรับสร้างฐานข้อมูลใหม่ มีการทดสอบกับฐานข้อมูลว่างและรันซ้ำ
- สำรอง PostgreSQL ในเครื่องพัฒนา และทดสอบกู้คืนในฐานข้อมูลแยกโดยเทียบจำนวนแถวและ digest ของข้อมูลทุกตาราง

## ใช้ migration อย่างไร

สำหรับฐานข้อมูลใหม่ที่เตรียมไว้เพื่อเปิดใช้งาน:

```sh
NODE_ENV=production npm run migrate
npm run build
npm run start
```

ต้องกำหนด DATABASE_URL และ PAYLOAD_SECRET ผ่านการตั้งค่าของ hosting ก่อนรัน เก็บ PAYLOAD_SECRET เดิมเมื่อย้ายระบบ ห้ามใส่ค่าจริงใน Git หรือข้อความสนทนา

อย่ารัน initial migration ทับฐานข้อมูลพัฒนาที่สร้างตารางด้วย schema push ไปแล้ว การทดสอบในโปรเจกต์นี้ใช้ฐานข้อมูลชั่วคราวที่แยกจากฐานข้อมูลหลัก:

```sh
npm run migrate:verify
```

เมื่อแก้โครงสร้าง CMS ครั้งต่อไป ให้สร้าง migration เพิ่มด้วย `npm run migrate:create -- <ชื่อการเปลี่ยนแปลง>` และทดสอบก่อนนำไปใช้งาน การสร้าง migration ไม่ได้เป็นการ deploy และระบบนี้ไม่ได้รัน migration อัตโนมัติเมื่อเริ่มเว็บ

## สำรองและตรวจการกู้คืนในเครื่องพัฒนา

```sh
npm run backup:local
npm run backup:verify -- .local/backups/<โฟลเดอร์ที่คำสั่งแรกสร้าง>
```

คำสั่งนี้ใช้ PostgreSQL จาก Docker Compose ของโปรเจกต์เท่านั้น ไม่ใช่คำสั่งสำรองฐานข้อมูล hosting ภายนอก ไฟล์สำรองอยู่ใต้ `.local/backups/` ถูก gitignore และจำกัดสิทธิ์การอ่าน เพราะมีข้อมูลบัญชีทีมงานอยู่ด้วย ไม่รวม `.env` หรือไฟล์รหัสผ่านสำหรับเข้าสู่ระบบ

การตรวจคืนสร้างฐานข้อมูลชั่วคราว กู้ archive ตรวจข้อมูลทุกตาราง และลบเฉพาะฐานข้อมูลชั่วคราวของคำสั่งนี้ ไม่มีการแทนที่ฐานข้อมูลหลัก

หากมีโฟลเดอร์ `media/` จะสร้าง archive เพิ่ม ตอนนี้ยังไม่มีไฟล์อัปโหลด การทดสอบที่ทำจึงยืนยันการกู้คืนฐานข้อมูล ส่วน archive ของ media ตรวจ checksum ได้ แต่ยังไม่ได้ทดสอบการแตกไฟล์คืน

## ข้อมูลที่ต้องเตรียมก่อน deploy

- Hosting สำหรับ Node.js, PostgreSQL และพื้นที่เก็บภาพที่คงอยู่หลัง restart
- โดเมนและ HTTPS
- ผู้ให้บริการส่งอีเมลสำหรับกู้รหัสผ่าน และข้อมูลบัญชีผ่านการตั้งค่าที่ปลอดภัย
- บัญชีทีมงานจริงและสิทธิ์ของแต่ละคน โดยไม่ใช้บัญชีทดสอบแทนบุคคลจริง
- การสำรองข้อมูลที่อยู่นอกเครื่อง hosting และขั้นตอนกู้คืนที่ทดสอบแล้ว

การเผยแพร่บทความเป็นขั้นตอนแยกจากการ deploy เว็บ ชื่อผู้ตรวจทานและวันที่อนุมัติจะบันทึกจากการตรวจทานจริงใน CMS
